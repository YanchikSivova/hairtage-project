# Hairtage

Веб-приложение для подбора средств по уходу за волосами. Пользователь отвечает на вопросы о состоянии волос и получает рекомендации, рассчитанные по составам продуктов. В проект входят пользовательский интерфейс, административный интерфейс, REST API и база данных.

## Компоненты

- `frontend/` — пользовательский сайт на React и Vite.
- `frontend-admin/` — интерфейс управления товарами.
- `Hairitage/` — REST API на Java 17 и Spring Boot.
- `db/init.sql` — схема PostgreSQL и начальные справочные данные.
- `docker-compose.yml` — запуск всех компонентов.

## Запуск

Требуется Docker Compose. Из корня проекта выполните:

```bash
docker compose up --build
```

После запуска:

| Сервис | Адрес |
| --- | --- |
| Пользовательский сайт | http://localhost:3000 |
| Административный интерфейс | http://localhost:3001 |
| REST API | http://localhost:8080 |
| Swagger UI | http://localhost:8080/swagger-ui/index.html |
| PostgreSQL | localhost:5433 |

Для остановки контейнеров выполните `docker compose down`. Данные PostgreSQL хранятся в Docker volume. `db/init.sql` выполняется при первом создании базы данных.

Compose-файл содержит учетные данные PostgreSQL для локальной разработки (`postgres` / `postgres`). Перед развертыванием в рабочей среде замените их и вынесите секреты из Compose-конфигурации.

## Возможности

- Регистрация и вход пользователя.
- Опрос из пяти вопросов, определение типа волос и подбор подходящих средств.
- Просмотр рекомендаций и истории результатов в аккаунте.
- Обновление данных пользователя.
- Создание, редактирование и удаление товаров; добавление товаров списком в административном интерфейсе.
- Расчет подходящих типов волос по категориям ингредиентов и их позициям в составе.

## REST API

Запросы к backend доступны на `http://localhost:8080`. При обращении через frontend Nginx использует префикс `/api` и перенаправляет запросы к backend.

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/csrf` | Получить CSRF-токен для сессии |
| `POST` | `/person/registration` | Зарегистрировать пользователя |
| `POST` | `/login` | Войти по `email` и `password` |
| `POST` | `/logout` | Завершить сессию |
| `GET` | `/person/checkAuth` | Проверить состояние авторизации |
| `GET` | `/person/accountInfo` | Получить профиль и историю результатов |
| `PATCH` | `/person/update` | Обновить данные пользователя |
| `POST` | `/person/selection` | Передать ответы опроса и получить рекомендации |
| `GET` | `/person/selection/auth` | Получить рекомендации по последнему результату пользователя |
| `GET` | `/person/selection/{hairTypeId}` | Получить рекомендации для указанного типа волос |
| `GET` | `/admin` | Получить список товаров (администратор) |
| `POST` | `/admin/create` | Создать товар (администратор) |
| `PATCH` | `/admin/update/{id}` | Обновить товар (администратор) |
| `DELETE` | `/admin/delete/{id}` | Удалить товар (администратор) |
| `POST` | `/product/addProducts` | Добавить список товаров (администратор) |

Для `/person/selection` передается JSON-массив из пяти ответов. Для первых четырех вопросов допустимы значения `1`–`3`; для последнего также доступно значение `4` — пропуск.

## Сессии и безопасность

Авторизация использует сессионную cookie и Spring Security form login. Изменяющие запросы должны содержать CSRF-токен: сначала запросите `GET /csrf`, затем передайте возвращенные имя заголовка и токен. Оба frontend-клиента выполняют это автоматически. Маршруты `/admin/**` и `/product/addProducts` доступны пользователям с ролью `ADMIN`.
